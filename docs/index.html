Blackwall Wiki

A self-hosted Discord anti-spam system combining a real-time bot for spam detection with a web dashboard for guild configuration — all backed by Discord OAuth2 authentication.

.NET 10 PostgreSQL 17 Redis 7 Blazor Server Docker
📝 Get Started ⚙ .env Generator 🔗 GitHub

Features

⚡ Real-time Spam Detection

Rate limiting, duplicate message detection, mention flooding, invite link blocking, and suspicious link filtering — all in real time.

🌐 Per-guild Configuration

Each server gets its own spam thresholds managed through the web dashboard. No one-size-fits-all.

🔑 Discord OAuth2 Login

Users authenticate via Discord. JWT tokens are issued for API and Web access.

🔄 Guild Permission Sync

A background service periodically synchronises guild manager permissions from Discord.

💻 Web Dashboard

Blazor Server UI for guild owners and managers to configure spam rules visually.

🤖 Account Scoring

Evaluates new members on join and assigns a threat score based on account metadata.

Architecture

Blackwall is a .NET 10 solution split into five projects:

ProjectDescription
Blackwall.CoreShared entities, DTOs, and configuration models
Blackwall.InfrastructurePostgreSQL persistence (EF Core) and Redis caching
Blackwall.BotDiscord gateway client — spam detection, guild events, background sync
Blackwall.ApiASP.NET Core Web API — OAuth flows, JWT auth, guild management endpoints
Blackwall.WebBlazor Server dashboard — authenticates against the API
How it fits together The API hosts the bot (as a hosted service), serves REST endpoints for the dashboard, and handles OAuth. The Web project is a Blazor Server app that calls the API. Both share the same JWT secret for authentication.

Prerequisites

  • .NET 10 SDK — Download
  • PostgreSQL 17+ — for persistent data storage
  • Redis 7+ — for caching
  • A Discord application with bot and OAuth2 credentials — create one at the Discord Developer Portal
Docker users If you're using Docker Compose, you don't need to install .NET, PostgreSQL, or Redis manually — they're all containerised.

Installation

1

Clone the repository

git clone https://github.com/pedrocavaleiro/Blackwall.git
cd Blackwall
2

Configure environment variables

Copy the example file and fill in your values:

cp .env.example .env

Edit .env with your configuration. See the Environment Variables section for a full reference, or use the .env Generator to interactively build your file.

Quick start Use the .env Generator tool — it provides one-click key generation for JWT secrets and AES encryption keys, plus inline help for every field.
3

Configure appsettings.json

In src/Blackwall.Api/appsettings.json, set the AllowedUsers array to the Discord user IDs permitted to register when APP__PRIVATE_INSTANCE=true:

"AllowedUsers": ["123456789012345678", "987654321098765432"]
Instance owner The owner (set via APP__INSTANCE_OWNER) is always allowed to register even if not listed in AllowedUsers.
4

Run Entity Framework migrations

Apply the database schema before starting the API:

dotnet ef database update --project src/Blackwall.Infrastructure --startup-project src/Blackwall.Api
Docker Compose Migrations are applied automatically on first run when using Docker Compose.
5

Start the application

Choose your deployment method — see the Deployment section below for detailed options.

appsettings.json

Beyond environment variables, some settings live in appsettings.json (and can be overridden with appsettings.Production.json):

API (src/Blackwall.Api/appsettings.json)

{
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft.AspNetCore": "Warning"
    }
  },
  "Blacklists": {
    "Defaults": [
      "https://blocklistproject.github.io/Lists/adguard/abuse-ags.txt",
      "https://blocklistproject.github.io/Lists/adguard/ads-ags.txt",
      "https://blocklistproject.github.io/Lists/adguard/phishing-ags.txt"
    ]
  },
  "AllowedUsers": [],
  "AllowedHosts": "*"
}
  • Blacklists.Defaults — Array of URLs to blocklist files used for suspicious link filtering. Defaults to the Blocklist Project AdGuard lists.
  • AllowedUsers — Array of Discord user IDs permitted to register when APP__PRIVATE_INSTANCE=true.

Overriding in production

Create appsettings.Production.json alongside the base file with only the keys you want to change. ASP.NET Core merges it at runtime:

{
  "Blacklists": {
    "Defaults": ["https://example.com/custom-blocklist.txt"]
  },
  "AllowedUsers": ["123456789012345678"]
}
Deploy safety The LXC deploy script excludes .env and appsettings.Production.json from rsync, so local customizations are never overwritten. appsettings.json (base defaults) is always synced.

Deployment

Blackwall supports three deployment methods. Choose the one that fits your infrastructure:

🐳 Docker Compose

Quickest setup. Everything containerised — PostgreSQL, Redis, API, Web, and Nginx.

🖩 Proxmox LXC

Provision a Debian 13 LXC container with automated setup scripts and systemd services.

💻 Bare Metal / VM

Install prerequisites directly and run natively. Full control for development or custom setups.

Deployment: Docker Compose

The quickest way to get everything running. Requires only Docker and Docker Compose.

Services

ServiceImageDescription
postgrespostgres:17-alpinePostgreSQL database with health check and persistent volume
redisredis:7-alpineRedis cache with health check
apiCustom (Dockerfile.api)ASP.NET Core API + embedded bot, depends on postgres & redis
webCustom (Dockerfile.web)Blazor Server dashboard, depends on api
nginxnginx:alpineReverse proxy on port 80, routes /api/ to API and / to Web

Steps

  1. Create your .env file (use the .env Generator).
  2. Set POSTGRES_PASSWORD in your environment or .env for the Postgres container.
  3. Run: 
    docker compose up --build
  4. The stack will be available on port 80 via the Nginx reverse proxy.

Nginx routing

  • /api/ → API container (port 8080)
  • / → Web container (port 8080, with WebSocket upgrade support for Blazor)
Docker internals Inside Docker, the API and Web run on port 8080. Nginx maps port 80 externally. The Web container calls the API at http://api:8080 using Docker's internal DNS.

Deployment: Proxmox LXC

The infra/lxc/ directory contains scripts for provisioning a Debian 13 (Trixie) LXC container and deploying published builds.

Step 1: Provision the container

Run setup.sh as root inside the LXC. It installs:

  • .NET 10 ASP.NET Core Runtime
  • PostgreSQL 17
  • Redis
  • Nginx
  • Creates the blackwall system user and directories at /opt/blackwall
  • Creates the PostgreSQL database and user (prints credentials)
  • Installs systemd services (blackwall-api, blackwall-web)
  • Configures Nginx as a reverse proxy
scp -r infra/lxc/ root@<lxc-ip>:/tmp/blackwall-setup
ssh root@<lxc-ip> "bash /tmp/blackwall-setup/setup.sh"
Save the credentials The setup script prints the PostgreSQL connection string. Save it — you'll need it in your .env.

Step 2: Place your .env

Place your .env at /opt/blackwall/.env on the LXC:

chown blackwall:blackwall /opt/blackwall/.env
chmod 640 /opt/blackwall/.env

Step 3: Deploy

From your dev machine, publish and upload both projects:

./infra/lxc/deploy.sh <lxc-ip>

This builds Release artifacts, uploads them via rsync, fixes ownership, and restarts the systemd services.

Windows deploy script

A PowerShell equivalent is also available:

.\infra\lxc\deploy.ps1 -LxcIp <lxc-ip>

systemd services

ServiceWorking DirectoryDepends On
blackwall-api/opt/blackwall/apipostgresql, redis-server
blackwall-web/opt/blackwall/webblackwall-api

Both services run with ASPNETCORE_ENVIRONMENT=Production and ASPNETCORE_FORWARDEDHEADERS_ENABLED=true.

Managing services

systemctl start blackwall-api blackwall-web
systemctl restart blackwall-api blackwall-web
systemctl status blackwall-api blackwall-web
journalctl -u blackwall-api -f
journalctl -u blackwall-web -f

Preserving config across deploys

The deploy script excludes .env and appsettings.Production.json from rsync, so user customizations are never overwritten. appsettings.json (base defaults) is always synced, meaning structural changes from the repo propagate automatically.

To override settings locally, create appsettings.Production.json in /opt/blackwall/api/ and/or /opt/blackwall/web/ with only the keys you want to change.

Deployment: Bare Metal / VM

Install the prerequisites directly on the host machine and run the projects natively. Useful for development or when you want full control.

Development

# Start PostgreSQL and Redis on the host (or point to remote instances in .env)

# Run the API + Bot
dotnet run --project src/Blackwall.Api

# Run the Web dashboard (separate terminal)
dotnet run --project src/Blackwall.Web

Production

Publish Release builds and host them behind a reverse proxy:

dotnet publish src/Blackwall.Api -c Release -o /opt/blackwall/api
dotnet publish src/Blackwall.Web -c Release -o /opt/blackwall/web

Then set up a reverse proxy (Nginx, Caddy, etc.) to route traffic:

  • /api/ → http://localhost:7001
  • / → http://localhost:7002 (with WebSocket support for Blazor)
Forwarded headers Set ASPNETCORE_FORWARDEDHEADERS_ENABLED=true so the app correctly respects proxy headers (X-Forwarded-For, X-Forwarded-Proto).

Account Scoring

Account Scoring evaluates new members' account metadata the moment they join the server and assigns a hidden threat score. It works independently of anti-raid — you can enable it even if velocity lockdowns are off.

Scoring Factors

FactorConditionPoints
Account ageLess than 1 day old+3
Less than 7 days old+2
Less than 30 days old+1
Profile pictureDefault avatar (no custom avatar set)+2
Username — numeric onlyUsername consists entirely of digits+2
Username — gibberishUsername is 6+ alphanumeric characters with no discernible pattern+2
Username — consecutive consonantsUsername contains 5+ consecutive consonants+1

Threat Levels

LevelScore RangeBehavior
Low0–1No action taken
Medium2–3Moderators are alerted in the audit log channel
High4+Moderators are alerted in the audit log channel

Configurable Actions

For medium and high risk accounts, you can independently enable auto-timeout:

  • Auto-timeout medium risk — automatically places medium-risk users in a timeout on join
  • Auto-timeout high risk — automatically places high-risk users in a timeout on join

If auto-timeout is disabled for a given level, moderators are alerted only and can manually decide whether to intervene. The timeout duration is configurable (default: 10 minutes).

Alerts All alerts are sent to the configured audit log channel as an embed containing the user, their score, account age, the specific risk factors that contributed, and the action taken.

Modules

Blackwall is organised into independent modules, each configurable per guild through the dashboard. Every module can be toggled on or off, and most support configurable actions (delete only, timeout, kick, or ban) with optional auto-lockdown. Modules stack — a single message can trigger multiple filters simultaneously.

General

Master controls for barrier activation and enforcement mode.

SettingDescription
Enable barrierWhen off, the bot will not process any messages in this server. All other modules are effectively disabled.
Dry runDetections are logged but no action is taken against the user. Useful for testing configuration changes before enforcing them.
LockdownInstantly denies Send Messages, Send Messages in Threads, and Create Public Threads for @everyone in every text channel and category via channel-specific permission overwrites. Higher-tier roles are unaffected. Can be toggled from the dashboard or via the /lockdown and /unlock slash commands in Discord.

Detection Matrix

Controls how the barrier detects and neutralizes spam, duplicate floods, and mass-mention attacks. Each filter runs independently and stacks with the infraction action set in General.

FilterSettingsDescription
Rate limitingWindow (seconds), max messages per windowCounts messages from a single user in a rolling time window. The next message after the limit triggers an infraction. The counter resets once the window expires with no new messages.
Duplicate detectionThreshold, window (seconds), cross-channel toggleTracks identical message hashes per user. When the threshold is reached within the window, the filter trips. Cross-channel mode counts duplicates across different channels; per-channel mode only counts within the same channel. Set threshold to 0 to disable.
Mention limitMax mentions per messageFlags messages that exceed the configured combined user, role, and @everyone/@here mention count as mass-ping spam.

Each detection filter has its own configurable action (delete only, timeout, kick, or ban), timeout duration (when applicable), message delete days (when banning, up to 7 days), and auto-lockdown toggle.

Link Blocking

Configures which external vectors are neutralized automatically.

SettingDescription
Block Discord invite linksDeletes messages containing discord.gg invite URLs.
Block external linksChecks message URLs against AdGuard blacklists and custom blocked domains.
Whitelist modeWhen on, blacklists are ignored and only domains in the custom domain list below are allowed. Everything else is blocked. Requires Block external links to be enabled.

Google Safe Browsing

Real-time threat check powered by a locally synchronized Global Cache from Google Safe Browsing. All URL checks are resolved locally against the synced cache — no URL data or hash prefixes are ever sent to Google. Only available when SAFE_BROWSING__ENABLED=true is set server-side.

SettingDescription
Enable Google Safe BrowsingChecks URLs that pass the blacklist/whitelist filter against Google's threat lists in real-time. Requires Block external links to be enabled.
Block levelUnsafe only blocks confirmed threats. Unsafe and Unsure also blocks URLs where the result is uncertain.

Blacklist Sources

AdGuard-format blacklist URLs. Domains from these lists are downloaded, merged, and cached in Redis. Refreshed daily. You can add from defaults (Blocklist Project lists), add custom URLs, or trigger a manual refresh. Hidden when whitelist mode is active.

Custom Blocked Domains

Individual domains to block in addition to the blacklists above. Subdomains are matched automatically. In whitelist mode, this list becomes the Allowed Domains list — only links to these domains are allowed and all other external links are blocked.

Module Actions (Links)

Each link protection module (invite links and external links) has its own configurable action, timeout duration, message delete days (when banning), and auto-lockdown toggle — same as the detection matrix.

Anti-Raid

Automatically deletes all active invite links when an abnormal surge of joins is detected. During the cooldown period the action cannot re-trigger.

SettingDescription
Enable anti-raidMonitor join rate and automatically pause invites when a raid is detected.
Join thresholdNumber of joins within the detection window that triggers the lockdown.
Detection window (seconds)Rolling time window used to count joins. Range: 5–300 seconds.
Cooldown (minutes)How long invites remain paused before the lockdown lifts automatically.

Account Scoring

Evaluates new members' account metadata on join and assigns a hidden threat score based on account age, profile picture, and username patterns. Works independently of anti-raid. See the Account Scoring section above for the full scoring table and threat levels.

SettingDescription
Enable account scoringEvaluate joining users' account metadata and alert moderators for suspicious accounts.
Auto-timeout medium riskAutomatically timeout medium-risk accounts on join. If disabled, mods are alerted only.
Auto-timeout high riskAutomatically timeout high-risk accounts on join. If disabled, mods are alerted only.
Timeout duration (minutes)How long the user is timed out when auto-timeout is triggered. Minimum: 1 minute.

Ban Management

Tools for sharing, syncing, and importing bans across Blackwall-managed servers.

FeatureDescription
Ban list sharingWhen enabled, your server's ban list becomes visible to other servers managed by Blackwall. Other server admins can import your bans. You control whether your bans are shared — importing is always available.
Your ban listSyncs bans from Discord into Blackwall's database. Click Sync from Discord to pull the latest ban list. Displayed with username, reason, and ban date.
Import bansImport bans from other Blackwall-managed servers that have ban list sharing enabled. Import the entire list or select individual bans. Users already banned in your server are automatically skipped.
Auto-syncAutomatically import bans from selected servers on a regular schedule. New bans added by the source server are imported automatically. Each auto-sync rule can be toggled on or off independently.

Audit Log

Select a channel where Blackwall will post an embed for each infraction: who triggered it, which filter fired, the message content, and the action taken. Leave blank to disable audit logging.

Module actions Most modules support the following action types: Delete only (removes the message), Timeout (temporarily mutes the user), Kick (removes the user from the server), and Ban (permanently bans the user, with optional message history purge up to 7 days). Each module can also independently trigger a server auto-lockdown when it fires.

API Documentation

When ENABLE_DOCS=true is set in your environment, the API exposes an OpenAPI spec and Scalar UI:

  • OpenAPI spec — /openapi/v1.json
  • Scalar UI — /scalar/v1
Production It's recommended to keep ENABLE_DOCS=false in production to avoid exposing API documentation publicly.
